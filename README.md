# 刃物 in the Dark — キャラクターシート

Blades in the Dark のキャラクターシートを日本語で管理する非公式のSPAです。
React / TypeScript / Viteで動作し、サーバーやデータベースは使いません。

## 対応範囲

基本7種の **Cutter・Hound・Leech・Lurk・Slide・Spider・Whisper** に対応しています。
英語版公式無料シートv8.2と公式SRDを参照しています。効果文はこのプロジェクトの参考訳・要約です。
特殊プレイブック（Ghost・Hull・Vampire）は未対応です。

- プレイブックごとの初期アクション、特殊能力、固有装備、知人、XP条件、情報収集の質問。
- プレイブックの固定3点に追加4点を初期配分し、アクション欄だけで確定できます。配分中は各最大2、確定後は4まで記録できます。
- 複数能力の取得、他の基本プレイブックの能力を取得するVeteran、自由記入能力。
- 能力ごとの選択・メモ・使用回数。Houndの狩猟動物、Leechの処方・設計と弾帯、LurkのExpertise、SpiderのForesight、Whisperの儀式など。
- MuleのLoad上限、Survivorのストレス枠、Vigorousの恒久的な治療区画、特殊鎧を使う能力の反映。
- 装備のLoad 0・1・2・3、複数個の宣言、薬品の使用枠、携帯コインのLoad集計。上限を超える場合も裁定用に記録できます。
- 個別の傷（レベル1・2は各2欄、レベル3は1欄）、治療4分割、通常鎧・重装・特殊鎧の使用。
- 個人Coin 4、Stash 40、プレイブックXP 8、各属性XP 6。
- JSON書き出し・取り込み、取り込み前・新規作成前のバックアップと復元。変更履歴は保存しません。

判定、トラウマ発生、傷の繰り上げ・回復、成長、ダウンタイムの効果は手動で処理します。
トラウマのチェック解除は入力訂正で、ルール上の回復ではありません。
1キャラクターを管理し、端末間の移動はJSONを使います。
ブラウザで使うツールです。シートは三列の紙面、傷の表、二列の装備という構図を保ちます。右列では属性ごとのアクションと抵抗値をまとめ、その下の経験値欄にプレイブックと3属性のXPを並べます。狭い画面ではシート領域を横スクロールします。詳細編集のフォームは画面幅に応じて並びを調整します。

## 使い方

画面上部には「シート / 編集」の切り替えだけを表示します。キャラクター名やストレス・トラウマ・コインはシート内で確認します。

- **シート**：プレイ中に使うストレス、傷、能力、装備、資産、XPを操作します。アクション値は小さな丸で表示し、操作できる四角いボックスと区別します。
- **編集**：初期設定、特殊能力、状態、装備、データを編集します。所属クルー名は「初期設定」で入力します。アクション値の作成時の配分・成長・入力訂正、知人の名前と親しい人物・ライバルの設定は「初期設定」で行います。シートの知人欄は表示専用です。

「初期設定」でプレイブック、身元情報、アクション値、知人との関係を編集し、「特殊能力」で能力を取得します。
アクション欄の斜線はプレイブックの固定3点、橙は初期配分、青は成長分です。横の補助欄に「初期配分：0/4点」「成長分：0点」を表示します。狭い画面では補助欄がアクションの上に移ります。
初期配分中は追加4点・各アクション最大2に制限します。4点を配り「初期配分を確定」を押すと、各アクションを4まで編集できます。特殊能力や人物設定の入力は確定条件に含めません。キャラクター全体の作成完了状態はありません。
成長の編集では固定点と確定した初期点を減らせません。「初期配分を修正」では初期点だけを訂正でき、確定時に反映します。「訂正をやめる」で変更を破棄できます。技能ごとの成長分を保持し、成長分を含めて4を超える初期点の追加はできません。
通常の成長上限3、Masteryによる上限4、能力や卓の裁定による追加点の適用は手動です。作成時の例外による追加点は初期配分の確定後に記録し、成長分の表示に含めます。その他の作成手順やルール説明は卓で確認してください。
出自の選択肢には6地域の特徴を添え、選択後は詳しい説明も表示します。出自 → 出自の詳細 → 経歴 → 経歴の詳細の順で縦に並べ、「出自の詳細」には家族の暮らしや育った環境などを記入します。地域の説明は公式Player's Kitの参考訳・要約で、[出自の調査資料](docs/research/heritages.md)に根拠をまとめています。
情報収集の質問例はシートの折りたたみ欄で参照できます。作戦の記録には自由メモを使います。クルー管理の専用画面はありません。以前の作戦メモ・情報収集メモ・クルーの詳細はJSON内に保持し、「データ」のJSON表示から確認できます。

既存人物のプレイブック変更では、名前・状態・資産・XP・共通装備を維持します。
切り替えると知人、固有装備の宣言・使用枠、情報収集メモ、取得済み特殊能力は新しい内容に置き換わり、アクションは固定3点に戻って初期配分を再開します。変更前の固有データと初期配分は保管します。

「装備」の「次の仕事を開始」は装備の宣言、薬品の使用枠、仕事ごとの能力使用回数、通常鎧と重装の使用をリセットします。
特殊鎧は「状態」のダウンタイム開始操作で別にリセットします。
能力の説明や卓の裁定に従って操作してください。

特殊能力の入力訂正は「編集 → 特殊能力」で、取得済みの能力名の横にある「取得を取り消す」から行います。
確認画面には、記録内容の削除と能力補正への影響を表示します。取り消した能力は再取得できますが、以前のメモ・選択内容・使用回数は戻りません。XPの返還は自動で行いません。

傷の本文を含むシートの入力は、その場でキャラクターに反映されます。確定ボタンは不要で、シート／編集を切り替えても入力内容を保持します。
「状態」ではストレス・資産・XPの増減をまとめて適用できます。操作の履歴と取り消し機能はありません。

## 保存と旧データ

現在の保存形式は **v2**、自動保存先は `bitd.character.v2`、保存タイミングは変更後300msです。ページを離れるときや非表示になるときは、保存待ちの内容をすぐに保存します。
取り込み前・新規作成前のバックアップは `bitd.character.backup` に保存します。
バックアップに失敗した場合は置き換えを中止します。

以前のv2のJSONも読み込めます。現在のシート内容を維持し、`log` の操作履歴は読み飛ばして、以後の保存・書き出しには含めません。
確定した初期配分は `initialActionRatings` に記録します。未確定では `null` です。この項目がない以前のデータはアクション値を維持し、初期配分を推測せず固定点だけを基準にします。必要に応じて「初期配分を修正」から記録できます。
旧形式v1のJSONと `bitd.character.v1` のブラウザ保存も読み込めます。
移行後はv2キーに保存し、元のv1キーは上書きしません。
名前、公式欄のアクション・能力・装備・資産・傷など、対応が明確な項目を移行します。
旧アクション値に初期値を加算しません。
独自の8属性、エッジ、武器ダメージなどは通常画面から外し、旧履歴とともに原データを丸ごと保管します。
上限修正で収まらない値や、対応が曖昧な項目の原データも「データ → 移行・変更前のデータ」で確認できます。
この保管内容はv2のJSON書き出しにも含まれます。

壊れた保存や未来版を検出した場合、自動保存を停止して原データを保護します。
明示的な取り込み・新規作成の前に、読めなかった原保存を `bitd.character.unreadable-backup` へ退避します。
保存に失敗した場合は画面に表示します。ブラウザ内だけの保存なので、重要なキャラクターはJSONでも保存してください。

## 開発環境

Node.jsの正確な対応範囲は `package.json` の `engines` を参照してください。
CIはNode.js 22系。ローカル検証環境はNode.js 24.18.0 / npm 11.16.0です。

```sh
npm ci
npm run dev
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

Windows PowerShellでスクリプト実行が制限される場合は `npm.cmd` を使います。
npmキャッシュは `.npmrc` により `.npm-cache/` へ保存されます。
`node_modules/`、`.npm-cache/`、`dist/` はGit管理対象外です。

## GitHub Pagesへの公開

`main` へpushすると `.github/workflows/deploy.yml` が品質チェックとビルドを実行し、公開します。
GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。
配信先は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
Viteの `base: './'` はサブパス配信のため維持しています。
