# 刃物 in the Dark — キャラクターシート

Blades in the Dark のキャラクターシートを日本語で管理する非公式のSPAです。
React / TypeScript / Viteで動作し、サーバーやデータベースは使いません。

## 対応範囲

基本7種の **Cutter・Hound・Leech・Lurk・Slide・Spider・Whisper** に対応しています。
英語版公式無料シートv8.2と公式SRDを参照しています。効果文はこのプロジェクトの参考訳・要約です。
特殊プレイブック（Ghost・Hull・Vampire）は未対応です。

- プレイブックごとの初期アクション、特殊能力、固有装備、知人、XP条件、情報収集の質問。
- 初期3点に追加4点を配分する作成支援。作成中は各アクション最大2、作成完了後は4まで記録できます。通常の成長上限3やMasteryの条件は卓で確認します。
- 複数能力の取得、他の基本プレイブックの能力を取得するVeteran、自由記入能力。
- 能力ごとの選択・メモ・使用回数。Houndの狩猟動物、Leechの処方・設計と弾帯、LurkのExpertise、SpiderのForesight、Whisperの儀式など。
- MuleのLoad上限、Survivorのストレス枠、Vigorousの恒久的な治療区画、特殊鎧を使う能力の反映。
- 装備のLoad 0・1・2・3、複数個の宣言、薬品の使用枠、携帯コインのLoad集計。上限を超える場合も裁定用に記録できます。
- 個別の傷（レベル1・2は各2欄、レベル3は1欄）、治療4分割、通常鎧・重装・特殊鎧の使用。
- 個人Coin 4、Stash 40、プレイブックXP 8、各属性XP 6。
- 変更履歴と直近の取り消し、JSON書き出し・取り込み、取り込み前のバックアップ。

判定、トラウマ発生、傷の繰り上げ・回復、成長、ダウンタイムの効果は手動で処理します。
トラウマのチェック解除は入力訂正で、ルール上の回復ではありません。
1キャラクターを管理し、端末間の移動はJSONを使います。
ブラウザで使うツールです。シートは三列の紙面、傷の表、属性ごとのXPとアクション、二列の装備という構図を保ちます。狭い画面ではシート領域を横スクロールします。詳細編集のフォームは画面幅に応じて並びを調整します。

## 使い方

画面上部の「シート / 編集」で切り替えます。

- **シート**：プレイ中に使うストレス、傷、能力、装備、資産、XPを操作します。アクション値は小さな丸で表示し、操作できる四角いボックスと区別します。
- **編集**：初期設定、特殊能力、変動記録、装備、作戦メモ、履歴、クルー、データを編集します。アクション値の作成時の配分・成長・入力訂正は「初期設定」で行います。

「初期設定」でプレイブックを選び、身元情報・追加4点・最初の能力を入力します。
「キャラクター作成を完了」を押すと、成長後のアクション値を記録できます。
出自・経歴に対応する各1点と自由な2点、親しい人物とライバルの選択は卓で確認してください。

既存人物のプレイブック変更では、名前・状態・資産・XP・取得能力・共通装備を維持します。
知人、固有装備の宣言・使用枠、情報収集メモの置き換えを確定前に表示し、変更前の内容は保管します。
アクションは維持するか初期値へ戻すか選べます。初期値の自動加算はしません。

「装備」の「次の仕事を開始」は装備の宣言、薬品の使用枠、仕事ごとの能力使用回数、通常鎧と重装の使用をリセットします。
特殊鎧は「変動記録」のダウンタイム開始操作で別にリセットします。
能力の説明や卓の裁定に従って操作してください。

シートの数値・宣言・使用状況の変更も履歴に残ります。
直近の記録後に別の編集がない場合に、その記録を取り消せます。
傷の本文は入力後に「記録」を押して確定します。

## 保存と旧データ

現在の保存形式は **v2**、自動保存先は `bitd.character.v2`、保存タイミングは変更後300msです。
取り込み前・新規作成前のバックアップは `bitd.character.backup` に保存します。
バックアップに失敗した場合は置き換えを中止します。

旧形式v1のJSONと `bitd.character.v1` のブラウザ保存も読み込めます。
移行後はv2キーに保存し、元のv1キーは上書きしません。
名前、公式欄のアクション・能力・装備・資産・傷など、対応が明確な項目を移行します。
旧アクション値に初期値を加算しません。
独自の8属性、エッジ、武器ダメージなどは通常画面から外し、旧履歴とともに原データを丸ごと保管します。
上限修正で収まらない値や、対応が曖昧な項目の原データも「データ → 移行・変更前のデータ」で確認できます。
この保管内容はv2のJSON書き出しにも含まれます。

壊れた保存や未来版を検出した場合、自動保存を停止して原データを保護します。
明示的な取り込み・新規作成の前に、読めなかった原保存を `bitd.character.unreadable-backup` へ退避します。
保存に失敗した場合は画面に表示します。ブラウザ内だけの保存なので、重要なキャラクターはJSONでも保存してください。

## 開発環境

Node.jsの正確な対応範囲は `package.json` の `engines` を参照してください。
CIはNode.js 22系。ローカル検証環境はNode.js 24.18.0 / npm 11.16.0です。

```sh
npm ci
npm run dev
npm run lint
npm run typecheck
npm test
npm run build
npm run preview
```

Windows PowerShellでスクリプト実行が制限される場合は `npm.cmd` を使います。
npmキャッシュは `.npmrc` により `.npm-cache/` へ保存されます。
`node_modules/`、`.npm-cache/`、`dist/` はGit管理対象外です。

## GitHub Pagesへの公開

`main` へpushすると `.github/workflows/deploy.yml` が品質チェックとビルドを実行し、公開します。
GitHubリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。
配信先は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
Viteの `base: './'` はサブパス配信のため維持しています。
