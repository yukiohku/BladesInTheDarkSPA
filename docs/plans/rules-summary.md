# サマリー画面の実装計画

作成日：2026年10月3日。状態：5章の画面・本文を実装済み。品質チェックとブラウザ確認を完了（200%拡大は未確認）。実装前の計画は `codex/rules-summary` ブランチのコミット `4f2243c` に保存済み。

「シート」「編集」に加えて「サマリー」を設け、プレイヤーがプレイ中に判定や関連ルールを素早く参照できるようにする。判定の手順と早見表を最初に置き、協力、抵抗、仕事の準備、ダウンタイムを整理する。経験値と成長はシート内の既存サマリーで参照する。ルール本文の照合と画面実装を段階的に進め、保存データを変更しない閲覧専用画面として完成させる。

## 目的と利用場面

- 判定前に、使うアクション、判定状況、効果、追加ダイスを確認する。
- 判定後に、出目の読み方、悪影響への抵抗、傷やストレスの扱いを確認する。
- 味方を助ける、過去の準備を描く、仕事を開始するときに、選べる手段を確認する。
- 仕事の合間に、回復、悪癖、ダウンタイム活動の手順を確認する。

読者はプレイヤーを中心とし、GMとの相談に必要な役割分担も短く示す。全文翻訳ではなく、その場の判断に必要な条件・手順・費用・結果を読める要約にする。

## 初回実装の範囲

初回の完成形は、以下の5章と出典案内を備えた共通ルールのサマリーとする。各段階を小さく実装しても、この範囲が揃うまでは初回実装の完了と扱わない。

| 章 | 掲載する内容 | 原典照合で重点的に確認する点 |
| --- | --- | --- |
| 判定 | アクション判定の流れ、ダイスの読み方、0個の場合、クリティカル、判定状況と効果、判定状況別の結果表 | プレイヤーとGMの役割、［優位］な状況の選択肢、結果と効果の区別、効果の段階とクロック進行の関係 |
| 判定を有利にする方法と協力 | 自分を追い込む、悪魔の取引、援助、集団行動、かばう、布石となる行動 | 費用、誰がストレスを受けるか、追加ダイスの併用条件、集団行動の参加者と代表結果、布石で改善する対象 |
| 悪影響への対処 | 悪影響の種類、抵抗判定、属性値の読み方、鎧、傷、ストレス、トラウマ | 抵抗の成立と軽減範囲の裁定、ストレス算出、同じ悪影響への抵抗回数、傷の適用条件、能力による例外 |
| 仕事の準備と進行 | 計画の種類と必要な詳細、初動判定、Loadと装備宣言、フラッシュバック、運勢判定 | 初動判定が決める範囲、フラッシュバックの費用と限界、運勢判定のダイス数と結果 |
| ダウンタイム | 活動回数と追加活動、6種類の活動の目的と基本手順、回復と治療、悪癖と過剰耽溺、個人のコインと貯蓄 | 戦争中や能力の例外、活動結果と改善費用、回復の進行・繰り越し、悪癖判定の属性、個人資産とクルー資産の区別 |

情報収集の手順・判定の使い分け・質問例は画面に掲載しない。クロックは効果や長期プロジェクトを理解するために説明するが、編集欄は追加しない。

経験値の獲得条件・記録先・セッション終了時の処理・成長の説明は、シートの経験値欄に集約する。ダウンタイムでは訓練を活動の選択肢として短く紹介し、XPの記録や成長については「シートの経験値欄を参照」と案内する。

### 今回の範囲に含めない機能

- ダイスローラー、成功確率の計算、判定結果に応じたストレス・傷・XPなどの自動更新。
- 経験値・成長の独立した章と、シートの経験値欄にある説明の再掲載。
- キャラクター作成の詳細ガイド、全特殊能力・全装備の再掲載、キャラクター別の補正値表示。
- クルー管理、派閥・縄張り・報酬・厄介事の詳細表、GM向け運営ルール。
- 特殊3プレイブック、Deep Cutsなど追加ルール、日本語版書籍の本文の転記。
- 印刷レイアウト、全文検索、お気に入り、閲覧履歴、独立したURLによる共有。

検索やキャラクター別表示は、初回の内容量と利用時の探しやすさを確認してから検討する。

## 画面構成と操作

### 上部の切り替え

上部の表示モードを「シート / 編集 / サマリー」にする。初回表示は引き続きシートとし、サマリーにはプレイブック未選択でも入れる。サマリーには編集タブを表示しない。

モードボタンの `aria-pressed` とキーボード操作を維持する。保存エラーは全モード共通の位置に表示する。編集に戻ったときの選択タブは既存のローカルstateで維持する。

### 本文の並び

1. 「ルールサマリー」の見出しを表示する。導入文は置かない。
2. 5章へ移動する目次を置く。
3. 「判定」に、矢印でつないだ手順と、ダイスの読み方・状況別の結果・効果とクロックの進行の表をまとめる。
4. 残りの章を目次と同じ順で並べる。
5. 原典リンクは調査文書に集約し、画面末尾に著作者・ライセンス・翻訳と再構成の説明をまとめる。各章末尾の出典一覧と先頭へ戻るボタンは掲載しない。

頻繁に参照する手順・費用・結果表は常時表示する。長い例や例外の補足だけを必要に応じて標準の `details` / `summary` に入れる。重要な併用条件や費用を折りたたみの中だけに置かない。

### レイアウト

シートと同じ紙色・インク・罫線を使い、黒帯の見出しと密度のある早見表にする。シートのロゴと英字見出しの書体も利用する。判定・協力・悪影響への対処の各章は本文の全幅に広げる。協力の章内は「追加の利益と費用」と「チームワーク」、悪影響への対処の章内は「悪影響・抵抗・鎧」と「傷・ストレス・トラウマ」を左右にまとめる。鎧の使用を左列の属性表の下に置き、左右の内容量を整える。仕事の準備と進行・ダウンタイムの章は広い画面で二列に並べる。幅800px以下では章と章内の二列を一列にし、本文の文字は13〜14pxを基本として、12px未満にしない。

広い画面では左に目次、右に本文を置く。幅1100px以下では目次を本文の上に並べる。背景色などのCSS変数をシートと共有し、シートの三列構成や横スクロールは維持する。

判定結果は「優位・リスキー・絶望的」の小さなタブで1つの表の領域を切り替える。初期表示はリスキー。タブ選択はローカルstateのみで、クリック・左右矢印・Home・Endに対応する。幅1000px超ではダイス・状況・効果の3表を横並び、幅601〜1000pxではダイスと効果を左、状況を右、幅600px以下では縦に並べる。画面全体の横スクロールを前提にしない。

目次には安定した章IDとアプリ内の移動操作を使う。ブラウザ標準のハッシュ移動を採用する場合も、GitHub Pagesのサブパスと既存の画面切り替えに影響しないことを確認する。移動先の見出しにフォーカスを渡し、キーボードや読み上げでも移動結果を把握できるようにする。

### 画面間の往復

サマリーはキャラクターを変更する操作を持たず、閲覧してもreducerの更新actionを発行しない。直前のシート入力が自動保存待ちでも、サマリーへの切り替えで消えないことを確認する。

編集タブ内の未確定の一時入力については、現状の画面切り替え時の扱いを確認し、サマリー追加によって挙動を悪化させない。初期配分の訂正中などは、保存済みデータと未確定入力を区別してテストする。

初回はサマリーへ入るたびに先頭を表示する。読む位置の復元は、実際の往復操作で必要性を判断する。

### 説明文の基準

- 技能名は〈破壊〉のように括り、判定状況と効果は既存の対訳を使う。新しい参考訳が必要な用語は、調査資料の対訳に追加してから本文に使う。
- 誰が行い、何を支払い、何が変わり、どこをGMが決めるかを文章で示す。
- ダイス追加、効果の段階上昇、判定状況の改善、判定結果の変化を分ける。
- 基本ルール、特殊能力の例外、アプリの入力手順を混ぜない。アプリで数値を入力できる範囲を、そのままルール上の上限として説明しない。
- 例は理解に必要な短いものを独自に作り、出典の長い本文や書籍の例を転記しない。
- 章ごとの原典リンクは調査文書にまとめる。SRDの利用区分と画面末尾の帰属表記は[既存の出典案内](../research/README.md#出典と利用区分)と[公式Licensing](https://bladesinthedark.com/licensing)に合わせる。

本文完成前に重点確認するのは、0個のダイス、［優位］な状況の結果、追い込みと取引の併用条件、抵抗と失敗した目的の関係、複数の悪影響、集団行動のクリティカル、傷の欄が埋まっている場合、トラウマ発生時、フラッシュバック内のダウンタイム活動、回復・悪癖の例外である。これらを一般的な成功・失敗の一行説明だけで済ませない。

ダミーデータを使う独立したブラウザ環境で、1440px、1024px、768px、390px、320pxの幅と、200%拡大を確認する。目次の使いやすさ、日本語の折り返し、表の読みやすさ、フォーカスの可視性、操作対象の押しやすさを確認する。シートの三列と横スクロール、編集の既存レイアウトも影響がないことを確認する。

実装後は `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` を実行する。ビルド結果もサブパス配信を想定して確認し、`base: './'` を維持する。実行できなかった確認や未解決の不具合は完了報告に明記する。
